# WT-CORRECTION-20261020

사용자가 승인한 운영 예외 처리 보완. 본인 ONGOING/COMPLETED/REJECTED 기록의 실제 출퇴근 시간과 사유를 제출하면 COMPLETED(사장 확인 대기)로 돌아간다. CONFIRMED 급여 기록은 수정하지 않는다. 기존 승인/반려 API에 expectedCorrectionCount를 추가하여 오래된 화면의 승인/반려를409로 거절한다. 정정 전 기록의 생략 기본값0은 호환 유지한다. 사장 웹 업데이트가 함께 필요하다.

- POST /api/worklogs/my/{id}/corrections: clockInAt,clockOutAt,reason(1~500),expectedCorrectionCount,expectedStatus.
- 본인 소유권 404, WORKER 역할, 종료>시작 및 미래 퇴근 거절, 다른 진행/완료/승인 기록과 겹침 거절. 현재 상태/정정 횟수가 바뀌면 409.
- 직원 행→최신 근무 기록 행 순서로 잠금. 승인·반려도 같은 잠금 규칙을 사용하여 수정/승인 경합을 직렬화.
- V5에 정정 횟수/최근 사유/반려 사유 및 이전·신청 시간/이전 반려 사유/상태의 이력 테이블 추가. 반려 사유를 응답에 포함하고 재제출 시 현재 반려 사유를 지운다. 이력은 유지한다.
- 사장 웹 기존 승인 대기 조회로 수정된 시간을 확인할 수 있다. 이력 전용 웹 UI와 승인 완료 기록의 재개방·급여 정산 수정은 후속이다.

검증: H2/실제 MySQL에서 정정·반려 재제출·타인 차단·입력/겹침·동시 정정·승인 경합을 검사하고 V5 Flyway startup 확인. 기존 전체 회귀 검사 유지. CI 결과는 PR에 기록한다.

병합 시 기존 개발 서버 자동배포와 V5 적용이 발생하므로 대표 최종 검토가 필요하다. 이전 V1~V4는 변경하지 않는다. 롤백은 추가 컬럼과 정정 이력을 보존하며 배포의 마이그레이션 호환 규칙을 확인한다. 자동 역DDL/이력 삭제는 하지 않는다. 실제 가게 기록에는 아직 적용하지 않는다.
