## New behavior and tests

- Reproduced a real disagreement: two 30-minute shifts at 10001 produce 10002 in
  owner summary, but 10001 in worker daily detail. Detail now sums the established
  per-record HALF_UP amounts. This intentionally changes detail by one won in
  that case; owner summary remains the arithmetic reference.
- Real Spring security/controllers/JPA test flushes and clears persistence before
  comparing independent expected amounts across direct, owner and worker APIs.
  Includes historical contracts, leap day, year/month boundary and offset input,
  minute truncation, exact stored record IDs, state and duration.
- Missing checkout -> correction -> rejection -> second correction -> stale
  approval rejection -> current revision approval checks payroll at each stage
  and both immutable correction rows.
- Concurrent duplicate approvals assert one 200/one 400, one persisted confirmed
  log, and one wage item worth 49380 (4h * 12345) for owner and worker. Existing
  correction-vs-approval and duplicate correction tests are reused. Backend CI
  runs this class on both H2 and isolated MySQL.
- `e2eServer` launches a loopback-only disposable H2 server on test classpath,
  never packages H2 in production. Memory DB disappears on process exit.

## Approved policy continuation and worker UI (supersedes open policy items above)

The user explicitly selected: **attribute the full shift to its UTC clock-in
month**, and **allow inactive employees historical reads while denying new work,
corrections and schedule mutations**. This does not authorize merge/deployment or
coverage exclusions.

Payroll uses `[UTC month start, next UTC month start)` on clock-in, with nonnull
clock-out, so overnight/year-end shifts are counted once. Wage date is explicitly
UTC in the service. Dashboard monthly wage uses the same UTC interval, wage date
and per-record rounding. History queries also use a half-open clock-in interval
so cross-boundary records remain visible. Daily attendance remains a local-day
view. The unit adapter expectation for the wage month is updated to UTC, and
persisted API tests check all three payroll APIs, next-month zero and dashboard
amounts, including leap/year-end and offset input.

Employee mutation policy executes after the existing worker lock and refresh;
resignation now takes the same worker lock. Owner historical reviews remain
allowed. `PostResignationIntegrationTest` tests 13 employee write routes (both
personal and identifier-based APIs) for 403 and unchanged DB state, plus retained
profile/history/schedule/payroll reads and owner approval. Total JUnit minimum is
266 with the 14-case retirement suite required by the audit.

Worker schedule approve/reject and correction/resubmission UI are implemented in
web #8. The full core browser flow now uses UI for those steps. New tests verify
revision conflicts, input retention, retry, missing-checkout/correction states,
retired action hiding and mobile dialog focus/cancel behavior.

`bash ./gradlew e2eServer -PwtE2eDatabase=mysql --no-daemon` supports only the fixed
loopback `13308/worktime_browser_e2e` disposable target with synthetic credentials.
It runs real Flyway migrations and Hibernate validation. The default H2 mode
retains create-drop. Test-only fixture controllers remain absent from production
JAR. Web CI provisions independent H2/MySQL jobs; browser setup verifies the actual
DB product via health, reports DB provenance and enforces the whole matrix.
